## Доработка индивидуального проекта

Создана база `data/learning_portal.sqlite`. Схема хранится в `sql/schema.sql`:

| Таблица | Поля |
| --- | --- |
| `courses` | `id INTEGER PRIMARY KEY`, `name TEXT`, `is_active INTEGER` |
| `materials` | `id INTEGER PRIMARY KEY`, `course_id INTEGER`, `title TEXT`, `category TEXT`, `publication_year INTEGER`, `is_published INTEGER`, `min_study_year INTEGER` |
| `students` | `id INTEGER PRIMARY KEY`, `course_id INTEGER`, `name TEXT`, `study_year INTEGER` |

Один курс связан с несколькими материалами и студентами. Поля `course_id`
ссылаются на `courses.id` через `FOREIGN KEY`. Ограничения `NOT NULL`, `UNIQUE`
и `CHECK` контролируют обязательность полей, названия курсов, категории,
логические признаки и диапазоны чисел. Созданы индексы по внешним ключам
и названию материала.

В `db/database.py` функция `get_connection()` открывает SQLite, включает
`PRAGMA foreign_keys = ON` и устанавливает `sqlite3.Row`. Поля результата
доступны по имени. `initialize_database()` выполняет SQL-схему;
`fetch_all()` и `fetch_one()` получают несколько строк или одну запись.

Модуль `db/import_json.py` читает исходные JSON-файлы, создаёт таблицы и
в транзакции заменяет их содержимое через параметризованные `INSERT` и
`executemany()`. Сначала вставляются курсы, затем связанные материалы и
студенты. Повторный запуск не создаёт дубликатов:

```bash
python -m db.import_json
```

Импортировано 3 курса, 5 материалов и 4 студента. JSON и консольное приложение
сохранены; веб-интерфейс получает данные из SQLite.

## SQL-запросы и веб-страницы

В `sql/queries.sql` сохранены 13 запросов: списки курсов и материалов;
активные курсы; опубликованные материалы первого года; материалы и студенты
с названиями курсов через `JOIN`; общее количество материалов и число
публикаций; количество материалов и студентов по курсам; распределение
по категориям; курсы с несколькими материалами через `HAVING`; материалы
курсов со старшекурсниками через подзапрос. Представлены как минимум два
запроса с `WHERE`, `JOIN`, `COUNT` и `GROUP BY`.

`courses.views.course_list()` получает список и количество связанных записей.
`course_detail()` выбирает курс, его материалы и студентов по ID.
`materials.views.material_list()` получает поисковую строку и категорию из
`request.GET`, добавляет условия `LIKE ?` и `category = ?`, передавая значения
отдельными параметрами. `material_detail()` соединяет материал с его курсом.
Результаты передаются в существующие шаблоны через контекст `render()`.

Новая страница `/courses/statistics/` показывает число материалов, публикаций
и студентов каждого курса. `COUNT(DISTINCT ...)` предотвращает повторный
подсчёт при соединении нескольких таблиц; `HAVING` фильтрует курсы по
минимальному числу материалов. Навигация и README обновлены. Поисковый
сценарий адаптирован к учебным материалам предметной области проекта.
