Описать сущности учебного портала и связи между ними средствами Django,
применить миграции и перевести веб-страницы на ORM с сохранением данных ПР7.

## Модели и перенос данных

| Модель | Поля, кроме первичного ключа id |
| --- | --- |
| Course | Уникальное название и признак активности |
| Student | ФИО, год обучения от 1 до 6, ссылка на курс |
| Material | Название, категория, год публикации от 1900 до 2100, признак публикации, минимальный год обучения от 1 до 6, ссылка на курс |

У каждого студента и материала один курс. От курса можно получить обе коллекции
через `course.students` и `course.materials`. Параметр `on_delete=PROTECT`
предотвращает удаление курса, пока с ним связаны записи.

Начальные миграции `courses` и `materials` создали таблицы в `db.sqlite3`.
Команда `import_pr7` перенесла 3 курса, 4 студентов и 5 материалов из
`data/learning_portal.sqlite`. Сначала сохраняются курсы, затем зависимые строки.
Команда сохраняет исходные ID и обновляет записи по ключу. Тест повторил импорт
и сравнил все поля каждой записи, включая внешние ключи, с исходной таблицей.

## Работа страниц

Каталог курсов показывает число материалов и студентов. Для подсчёта используется
`Count(..., distinct=True)`, чтобы при соединении двух коллекций каждая запись
учитывалась один раз. Карточка курса выбирает через `values()` только поля,
нужные для списков. На странице статистики `aggregate()` даёт итоги всей
библиотеки, а `annotate()` рассчитывает показатели каждого курса.

В каталоге материалов строка поиска проверяется по названию материала и курса.
Категория и исключение черновиков уточняют выборку, затем применяется сортировка.
`Paginator` делит результат на страницы по две записи. При переходе сохраняются
параметры запроса. Карточка материала загружает связанный курс вместе с материалом
через `select_related()`. Создание, изменение и удаление записей доступны в Django
Admin. В README описаны установка, миграции, импорт и запуск с панелью SQL.
