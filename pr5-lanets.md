## Доработка индивидуального проекта

В существующий репозиторий добавлен Django-проект `learning_portal`.
Файл `manage.py` запускает административные команды; `settings.py` содержит
настройки приложений, шаблонов и локализации `ru-RU`, `Europe/Moscow`.
В `requirements.txt` добавлена зависимость `Django==5.2.*`.

Созданы приложения `homepage`, `courses`, `materials`. Корневой
`learning_portal/urls.py` распределяет запросы через `include()`, а файлы
`urls.py` приложений определяют конкретные маршруты:

| URL | Представление | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index` | Главная страница |
| `/courses/` | `courses.views.course_list` | Список курсов |
| `/courses/<int:course_id>/` | `courses.views.course_detail` | Курс, его материалы и студенты |
| `/materials/` | `materials.views.material_list` | Список материалов |
| `/materials/<int:material_id>/` | `materials.views.material_detail` | Карточка материала |

На этапе ПР5 представления загружали JSON через функции `storage.py` и работали
с объектами `Course`, `Material`, `Student`. Для поиска материала добавлена
`find_material_by_id()`. Существующая `find_course()` использовалась для курса.
Числовой идентификатор передавался из URL аргументом представления.

HTML формировался в Python-функциях и возвращался через `HttpResponse`.
Общая функция `page(title, content)` задавала каркас документа, навигацию и
подключение Bootstrap. Динамические строки экранировались через `escape()`.
Карточки содержали названия, связанные курсы, категории и статусы публикации.
При отсутствии объекта возвращался ответ со `status=404`; для неизвестного
адреса зарегистрирован `handler404`.

Консольное приложение, объектная модель, JSON-хранилище и тесты ПР3 сохранены.
В README добавлены запуск Django и адреса страниц. Описанное состояние
зафиксировано в коммите ПР5; последующие работы изменили реализацию представлений.
